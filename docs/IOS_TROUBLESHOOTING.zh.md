## 专用早拦与保护边界

内部引擎为 4.1.1。主配置引用 24 个远程资源：11 个保护表、1 个 `ads-storm.list`、1 个 `ads.domainset`、11 个功能表。导出校验清单覆盖 25 个数据文件，包含兼容 `ads.list`；静态探针共 210 个。主配置继续使用 GitHub raw 资源，每日更新间隔为 86400 秒。

只将截图中已有的 9 个明确广告端点放入专用 `ads-storm.list`，使用 `REJECT-DROP,pre-matching`；完整广告大表仍用普通 `DOMAIN-SET` 与 REJECT。按 [Surge 官方拒绝策略说明](https://manual.nssurge.com/policies/reject.html)，普通 REJECT 在 30 秒内触发 50 次后会自动升级；pre-matching 自 Surge iOS 5.14 起可提前在 DNS/TCP 层拒绝，UDP 仍走普通规则。早拦优先于全部普通白名单，因此不能只靠白名单在前保护业务。

生成器只保留最终清洗广告表仍覆盖的精确主机，并排除全部现有及历史保护范围；新增保护后，相交早拦项会自动移除。`et.tanx.com`、`userlink.alicdn.com` 在截图中走直连；仅凭这些连接记录不能确定其具体请求用途，因此此次没有扩大封锁其父域。Apple、邮箱及 OCSP 的 DIRECT 与正常活跃状态本身也不是配置错误证据。

## 空节点与资源失败分开检查

公开配置按要求保留 `ipv6 = false` 和空 `[Proxy]`。请在自己的私有副本中填写节点，保留已确认的策略组成员顺序，再检查名称引用及实际可用节点。空组可能回落到 SUBSTITUTE/DIRECT；Smart 不接受用内置 REJECT 成员填补空组。此现象不能证明国家选择或密码错误。

本次独立获取 raw 上的 `ads.domainset` 和 `cn.list` 均为 HTTP 200，内容完整；这只证明该次获取成功。iPhone 报错时的具体网络路径与原因尚未确证，不能据此宣布手机资源加载已修复，也不能假定远程资源下载一定遵循某条分流策略。不添加未经官方支持的 `force-policy` 等参数。

先运行配置检查并确认节点可用，再在 Surge 手动更新外部资源，记录具体失败 URL、时间、错误原文及网络类型。分别在 Wi-Fi 和蜂窝网络复核；配置成功导入、服务端发布成功与手机实际下载成功是三个独立结果。
